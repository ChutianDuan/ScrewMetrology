## 运行方式

先沿用 README 的 CMake 配置，再构建无需窗口的学习入口：

```sh
cmake --build build --target inspect_measurement
build/inspect_measurement data/synthetic/images/rotation_1.png \
  config/synthetic.yaml result/diagnostics/normal
build/inspect_measurement data/mvtec_screws/images/screws_153.png \
  config/measurement.yaml result/diagnostics/reflection
build/inspect_measurement data/synthetic/edge_cases/touching.png \
  config/synthetic.yaml result/diagnostics/touching
```

三个位置参数依次为图像、配置 YAML、输出目录。合成数据不存在时，先运行 `build/generate_samples data/synthetic`；真实图片的获取方式见 [README](../README.md#dataset)。没有图形桌面也能保存这些输出。成功返回 0，参数、读图或保存失败返回 1。

该入口采用 `mixed` 展示模式，没有加载尺度或配方，因此 `NOT_EVALUATED` 是预期状态。原始灰度仍用于细化，过程记录不提供曝光补偿或新的预处理。

`main_test` 继续显示原来的 3×4 比较面板，并额外把当前 **Lab/PCA** 组合的过程记录保存到 `result/main_test/process/`。其余八个组合继续保存原有详情；窗口操作仍是 Q／Esc 或关闭窗口。

每个实验使用独立输出目录。程序不自动删除旧文件；同一目录复用时，以本次 `observations.md` 列出的目标为准。生成图片和 CSV 是可再生运行结果，保存在忽略的 `result/` 中，没有复制进文档或数据集。

## 输出与坐标约定

| 文件 | 内容与用途 |
| --- | --- |
| `segmentation.png` | 3×4 分割与筛选面板：原图、Lab 通道、颜色／暗部条件、形态学阶段、连通域过滤和外轮廓过滤 |
| `candidates.csv` | 连通域像素面积与外轮廓几何面积分阶段记录，包含接受／拒绝及原因；未计算的字段为空或 `null` |
| `object_N.png` | 每个目标的 3×2 面板：图像采样位置、局部掩膜、宽度剖面、判定摘要、成功／失败边缘曲线 |
| `object_N.profile.csv` | 截面索引、s、上下边界、原始／平滑宽度、两类基线与阈值、分界标记 |
| `object_N.edges.csv` | 所有实际尝试的边缘采样，包含位置、法线、灰度、梯度、最大／竞争峰和细化偏移 |
| `observations.md` | 中文观察记录、完整质量原因以及当前各目标文件链接 |
| `measurement.json`、`mask.png`、`overlay.png` | 无窗口入口额外保存的正式测量结果和常规图像输出 |

`candidates.csv` 的 `index` 是连通域标签或外轮廓提取顺序，两种阶段的索引不能直接对应，也不等于最终目标编号。

N 是本图按质心 `(y,x)` 排序后的目标编号，不是跨图像跟踪 ID。局部掩膜的列／行坐标为 `(u,v)`，对应 `s = u + local_s_origin`、`t = v + local_t_origin`。宽度剖面的横坐标是 **s 像素坐标**；`boundary_index` 是截面数组索引，两者不能混用。

边缘曲线横坐标是相对粗边缘点的法线偏移：灰度从 `−edge_search−1` 开始采样，梯度从 `−edge_search` 开始。梯度采用左侧纵轴，灰度采用右侧 0～255 纵轴；两条曲线分别缩放显示，以免弱梯度被灰度范围压扁。显示缩放不会改变采样或计算结果。

CSV 中 `null` 表示未计算、不可用或失败，不代表 0。出界且首个采样点就失败时也保留一条拒绝记录，灰度和梯度为空值。关闭亚像素时不为展示额外采样，边缘 CSV 只有表头。

## 怎样阅读面板

按三个问题顺序阅读：mask 是否代表工件？局部方向与宽度是否合理？细化为何被接受或拒绝？

分割面板第二行的 `b <= ...` 与 `L <= ...` 显示两条 Lab 条件。`invert=false` 时，在取并集后整体取反，阈值结果格显示的是取反后的实际前景。第三行筛选图中绿色表示保留、红色表示拒绝。使用 Otsu 或自适应阈值时，未参与计算的 Lab 格明确显示未记录。

宽度图的颜色含义：

- 灰色：原始截面宽度；黄色：最多五点中位数平滑后的剖面。
- 绿色：中间 30%～70% 的杆宽基线。
- 橙色：`head_ratio × shaft_baseline`，用于检查是否单端扩大及连续窄段。
- 青色虚线：`head_ratio × narrow_baseline`，用于两端异常扩大检查。
- 紫色竖线：识别出的头杆分界，与局部掩膜中的紫线对应。

头杆分析不满足细长与特征值比条件时，两条阈值线不显示，摘要中 `head eligible = no`；存在基线不等于已执行头部判定。没有识别出分界时，不绘制一个猜测位置。

梯度图显示一次成功与一次失败的实际调用。成功取首个接受的样本；失败优先选竞争峰，否则选有完整梯度的拒绝样本，最后才展示出界等不完整记录。原图格的绿／红采样短线分别对应这两张曲线，不代表某种分类真值。

实心红点是最大梯度峰，红色空心圆是其两侧邻点；紫色空心圆标出竞争峰。只有接受的样本绘制三点抛物线，绿色竖线是实际返回的细化位置，灰色竖线是粗边缘。失败样本没有拟合曲线，也不会用零偏移伪装成功。

| 边缘原因 | 如何解释 |
| --- | --- |
| `accepted` | 峰、邻点和拟合检查通过，返回有符号偏移 |
| `out_of_image` | 双线性采样的四邻域出界，曲线可能不完整 |
| `peak_at_search_boundary` | 最大峰位于搜索端点，缺少拟合邻点 |
| `weak_gradient` | 内部最大峰低于 `gradient_min` |
| `competing_peak` | 相距超过 2 点的另一局部峰不低于最大峰的 80%，拒绝盲选 |
| `flat_peak` | 曲率不足以形成稳定的凹抛物线峰 |
| `unstable_fit` | 拟合偏移超过 0.75 px，保留像素结果 |

单个边缘成功不等于整体细化成功。两端总长、整体宽度和有效截面比例等仍须通过原有检查；`refined` 也不等于几何可靠或公差 OK。

## 正常螺钉案例

**输入与配置：** `rotation_1.png`，`config/synthetic.yaml`。这是一张 17° 的合成螺钉，用 Otsu 观察纯几何。2026-10-05 保存结果包含一个可靠目标。

**观察结果：** 主轴约 16.971°，杆宽基线 19 px，两端剖面中位数为 39／19 px。头部阈值 `1.25 × 19 = 23.75 px`，只有负端超过阈值，因此 `head_end=-1`。分界索引 31，对应 `s≈−57.698 px`；紫线在局部掩膜与剖面上的位置一致。199 个尝试截面全部成功，整体状态为 `refined`。

**如何复盘：** 打开 `object_1.profile.csv`，找到分界及后续两个连续窄截面，核对索引到 s 的转换。头部长并非直接把 31 当作像素长度；它是分界 s 减去原始轮廓投影下限。原始截面与轮廓投影来自不同离散表示，因此杆宽基线 19 px 不应被解释为生成器的 20 px 真值已经变了。

这个案例所有尝试的边缘均成功，右下格明确显示没有拒绝样本；不会为凑齐面板人为制造失败。连续模型尺寸与整数轮廓定义的差异见 [README](../README.md#head-tail)。

## 真实反光与纹理案例

**输入与配置：** `screws_153.png`，`config/measurement.yaml`。原图存在金属反光与木纹，当前配置保留八个候选。这里选 **目标 1** 作为失败解读，不把它当作精度真值或单一反光因素实验。

**观察结果：** 杆宽基线 46 px，两端中位数 46／37 px，都不超过头部阈值 57.5 px，因此头杆分界缺失。局部掩膜和剖面存在明显缺口、波动；几何原因包含 `possible_touching`，这只是形状启发式，单个分离工件的分割损坏也可能触发。

截面细化成功 380／698，约 54.4%，低于要求的 60%，记录 `subpixel_low_quality` 并回退。右下实际样本出现两个相距超过 2 点的相近梯度峰，被 `competing_peak` 拒绝；其他采样还可能因弱峰或搜索端点峰失败。

**如何复盘：** 先比较 L/b 条件与形态学后的 mask，检查反光区域和背景是否使轮廓缺失或产生凹陷；再看宽度剖面与梯度记录。当前样本展示了多峰和缺失的现象，不能仅据这张图认定所有失败都由曝光造成。软件增强的效果需要路线第四阶段的单因素实验验证。

## 疑似粘连案例

**输入与配置：** 合成 `edge_cases/touching.png`，`config/synthetic.yaml`。生成器在螺钉旁连接了一块暗矩形，用于验证异常剖面，不是实物多螺钉测量真值。

**观察结果：** 当前主轴约 5.659°。中段被连接区域撑宽，杆宽基线为 44 px；两端中位数都为 29 px，均未超过普通头部阈值 55 px，所以 `head_end=0`，无分界。

较低四分位基线仍为 19 px，其检查阈值为 23.75 px。两端的 29 px **都超过这条青色虚线**，因此记录 `possible_touching_two_ends`，使几何不可靠。只看橙色的 55 px 线就无法解释这个拒绝原因，这也是面板额外展示低四分位基线的目的。

**如何复盘：** 对比正常案例，指出中段变宽怎样影响中位数基线，以及较低基线为何能补充异常检查。该样本仍有 256／262 个截面成功细化，整体为 `refined`，但 `reliable=false`；成功找到灰度边缘不会自动修复工件身份或粘连问题。

## 实现与验证范围

- [diagnostics.hpp](../include/screw/diagnostics.hpp) 定义旁路结构；不改变 `Object` 或测量 JSON schema。
- [segmentation.cpp](../src/segmentation.cpp) 在阈值、形态学和候选筛选发生时保存快照与原因。
- [metrology.cpp](../src/metrology.cpp) 保存实际局部栅格、剖面、基线、分界、采样及拒绝原因；关闭观察时不收集这些数据。
- [pipeline.cpp](../src/pipeline.cpp) 让过程记录与排序后的目标同序、同编号。
- [diagnostics.cpp](../src/diagnostics.cpp) 仅负责绘图和旁路文件保存；[inspect_measurement.cpp](../src/inspect_measurement.cpp) 是无窗口入口。

2026-10-05 在项目现有 OpenCV 5.0.0 环境验证：CTest 9/9 通过。观察开关测试覆盖三种分割、正／反前景、启用／关闭细化及多目标、粘连、空图共 36 组；逐字比较正式 JSON，并检查未导出的测量端点、分界、局部栅格与排序对应关系。另覆盖成功采样、出界、弱峰、竞争峰、短剖面、空图保存及无窗口入口错误路径。

39 张合成图的 px／mm／关闭细化流程、16 张代表图九种分割与主轴组合，与重构前基线比较：303 份 JSON／JSONL 和 668 张解码图像一致，仅排除批次耗时。实验入口原有总览和九张详情图也逐像素一致；过程记录是新增旁路产物。窗口按键与关闭事件未实测，无窗口保存与上述面板生成已验证。

阶段二的三种主轴量化对比仍待开展；已有同图视觉面板和结果一致性验证不能替代方法选型的误差报告。
